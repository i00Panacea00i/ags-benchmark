# 小白入门指南 —— 一篇看懂这套系统

> 本文档面向**没有任何背景**的读者。不需要懂云服务、不需要懂代码，
> 只要会开机、会复制粘贴命令就能读完。
> 读完后你会明白：这套系统在干嘛、由哪些零件组成、怎么跑起来、坏了怎么办。

---

## 1. 一句话说清这套系统

**它是一座全自动"出题工厂"：从 GitHub 上真实的软件 bug 里，
自动生产出一套能机器自动判分的编程考题，并自动质检、自动入库。**

为什么要这么做？因为要测试 AI 编程助手（agent）的水平，需要大量
"题目 + 标准答案 + 自动评分"的真题。人工出题太慢，这套系统把它全自动化了。

## 2. 先认识 6 个名词（每个只要 30 秒）

| 名词 | 大白话解释 | 生活类比 |
|---|---|---|
| **AGS** | 腾讯云提供的"沙箱服务"：能一键开出一个个干净、隔离的小电脑，用完即删 | 一栋可无限扩建的考试楼 |
| **沙箱（实例）** | AGS 开出来的那台"小电脑"，里面随便折腾，删了也不心疼 | 一间独立考场 |
| **镜像** | 制作沙箱的"模板"——同一个模板能开出一模一样的无数间考场 | 教室的装修图纸 |
| **agent1（制作员）** | 住在沙箱里的自动化程序，负责把 bug 改编成考题 | 出题老师 |
| **agent2（质检员）** | 也是住在沙箱里的程序，负责验证考题质量 | 质检员 |
| **数据集** | 最终产品：一道道考题打包成的题库 | 装订成册的试卷集 |

> 记不住没关系，后文遇到时回这张表查即可。

## 3. 一道考题是怎么诞生的？（完整故事版）

第 1 步到第 7 步，每一步都对应系统里的一次自动化操作：

```
①  找素材     GitHub 上有人报了个 bug（"这个函数在 Windows 上报错了"），
              后来有人修好了，还补了测试代码。这个"bug + 修复"就是原材料。

②  出题       agent1 把它改编成标准考题：
                题目描述   = bug 报告改写成独立可读的问题
                标准答案   = 那份修复代码
                评分标准   = 那批测试代码

③  自检含金量  agent1 亲自验证："不给答案时测试必须挂；给了答案测试必须过"。
              两头都成立，这道题才有区分度（术语叫 F2P，见 §8 术语表）。

④  打包       考题、答案、评分标准、做题所需的项目代码，全部打包。

⑤  质检       agent2 拿着打包好的题，另开一间考场，按考试流程完整走一遍：
                · 按标准答案做 → 必须全对，而且连做两遍结果一致
                · 不按答案做   → 必须挂（防止题目太水）
              任何一条不满足，这道题作废并记录原因。

⑥  登记       三关全过 → 正式写入题库（数据集）。写之前还要查台账：
              同一道题绝不入库两次。

⑦  收摊       所有考场用完即拆，不留垃圾。下次考试开新考场。
```

**这就是全部。** 系统里所有代码、配置、文档，都是在把上面 7 步做得
**更快（并发）、更省（复用）、更稳（出错自动重试）**。

## 4. 一张图看懂整个系统

```
        ┌─────────────────────────────────────────────┐
        │  教务处（编排器 driver，一台普通电脑上运行）      │
        │  · 发题目单（哪些 bug 要做成考题）               │
        │  · 查台账（这题做过没？做过的跳过）               │
        │  · 分配考场、收卷子、登记成绩                    │
        └───────────────┬─────────────────────────────┘
                        │ 统一调度（走 AGS 的"总机"）
        ┌───────────────▼─────────────────────────────┐
        │            AGS 考试楼（三种考场）               │
        │                                             │
        │  出题间 ×N（可上网）    →  agent1 在此出题       │
        │  质检间 ×N（可上网）    →  agent2 在此监考       │
        │  考场 ×N  （断网！）    →  考题在此被执行        │
        │                                             │
        │  备用考场（预热池）：提前开好放着，随到随用         │
        └───────────────┬─────────────────────────────┘
                        │ 成品归档
        ┌───────────────▼─────────────────────────────┐
        │  档案室：考题入库（COS/文件） + 装修图纸仓（TCR）  │
        └─────────────────────────────────────────────┘
```

三个常见疑问，先在这里答掉：

- **为什么考场要断网？** 防作弊。考题的评分只看代码本身，断网保证成绩
  真实反映能力。而断网的考场怎么"收到"考题？——考题是管理员从门口
  递进去的（技术上叫 files 注入，走的是管理通道，不走网络）。
- **质检间为什么能上网？** 质检员要自己开考场、递考题，得能呼叫物业（AGS 总机）。
- **为什么要有备用考场？** 开一间新考场要等 4 秒多。提前开好放着，
  考生随到随进，这 4 秒就省掉了。实测备用考场让"等考场"时间变成 0。

## 5. 三大设计需求，大白话版

| 需求 | 大白话 | 系统怎么做 | 实测效果 |
|---|---|---|---|
| **去重检测** | 同一道题绝不出两次 | 三道关卡：领题时查台账（claim）；入库时查题号和来源链接（双键）；考场模板全楼共用，不存在同题多模板 | 两关冒烟测试全过 |
| **快速横向扩展** | 想多出题？多搬几台电脑来就行 | 每台电脑上的教务处都是"临时工"，台账放在公共档案室（COS），谁先领题归谁，互相不用打招呼 | 同时开 40 间考场零失败 |
| **无状态运行** | 任何机器随时断电，重启接着干 | 所有重要东西都存档案室；考场用完就拆；出问题直接重跑同一条命令，系统自动跳过做过的 | "重试即恢复"，无需人工清理 |

## 6. 动手跑一遍（复制粘贴级教程）

> 前提：已有人帮你完成"一次性准备"（开通云服务、拿密钥）。若没有，
> 把本文档发给管理员，对照《使用手册》§1-§2 完成。

### 第 1 步：填配置（只做一次）

```bash
cd ags-benchmark-architecture
cp deploy/env.example deploy/.env
nano deploy/.env      # 或任何编辑器
```

只需要真正填 3 样东西（文件里有注释指路）：

| 要填的 | 去哪拿 | 类比 |
|---|---|---|
| `E2B_API_KEY` | AGS 控制台 → API Keys 页面 | 考试楼门禁卡 |
| `TCR_REGISTRY` | 容器镜像服务的实例地址 | 装修图纸仓地址 |
| `ROLE_ARN` | 管理员提供 | 图纸仓借阅证 |

保存退出（nano：Ctrl+O 回车，Ctrl+X）。

### 第 2 步：确认考场都开着（日常检查）

```bash
set -a; source deploy/.env; set +a
tccli ags DescribeSandboxToolList --region $TCR_REGION
```

看到三个工具都是 **ACTIVE** 就绪（`bench-builder` / `bench-validator` / `bench-base`）。
任何一个不是 ACTIVE → 停，把输出发给管理员（对应排查指南 T03）。

### 第 3 步：批量出题

```bash
bash examples/run_maker_batch.sh
```

终端会滚动输出。看懂三个关键行就够了：

```
[pypa/packaging#1204] agent: {"result": "success", "f2p": 3, ...}   ← 这题出好了
[pallets/click#3571]  ✅ 入库: F2P 6 / P2P 20                       ← 已写进题库
[make] 完成: {'success': 3, 'filtered': 1}                          ← 批次小结
```

`filtered` 不是报错！是质检规则正常淘汰（比如题目太水/测试不稳定）。

### 第 4 步：批量质检（跨考场验证）

```bash
bash examples/run_validator_batch.sh
```

结果文件 `output/validate-results.jsonl` 里每行一道题：

| 看到 | 意思 |
|---|---|
| `"result": "validated"` | 质检通过，题目合格 |
| `"result": "rejected"` | 质检不通过（后面跟着原因） |
| `"result": "error"` | 设备问题，重跑即可（系统会自动跳过做过的） |

**到这里你就完成了完整流程。** 想多出题：把更多 bug 编号加进
`/tmp/units.json` 再跑第 3 步；想多台机器一起跑：把整个目录拷到
新机器，改配置里 `CLAIM_BACKEND=cos`，跑同样的命令。

## 7. 出错了怎么办？（最常见的 6 种）

| 你看到的 | 一句话原因 | 一句话处置 |
|---|---|---|
| `401 Invalid API key` | 门禁卡失效了 | 控制台重新办卡，更新 `.env`（T01） |
| 推送镜像 `401` | 图纸仓的临时通行证过期了（约 1.5 小时寿命） | 程序每批自动换新证；手动操作先跑一次刷新命令（T02） |
| `LimitExceeded.SandboxInstance` | 同时开的考场超过上限了（约 50 间） | 程序会自动等位；总出现就把 `--concurrency` 调小（T04） |
| `SandboxTool is not active` | 考场类型创建时图纸还没传上去，卡死了 | 先传图纸再重建考场类型（T03，操作见使用手册 §6） |
| 终端大量 `filtered` | 不是故障——质检在正常淘汰不合格题目 | 无需处理 |
| 跑到一半机器重启了 | 没关系 | 原命令重跑一遍，做过的会自动跳过 |

其他 14 种情况见《排查指南》（docs/TROUBLESHOOTING.md，按症状查表）。

## 8. 术语表（速查）

| 术语 | 大白话 |
|---|---|
| F2P（fail_to_pass） | "修复前挂、修复后过"的测试——证明题目有含金量 |
| P2P（pass_to_pass） | "修复前后都过"的测试——证明修复没弄坏别的东西 |
| baseline | 不给标准答案做一遍题（必须挂，否则题目太水） |
| answer | 给标准答案做一遍题（必须全过） |
| 预热池（warm pool） | 提前开好的备用考场 |
| claim（认领） | 领题登记——防止两台机器做同一道题 |
| manifest | 一道考题的"清单页"：题号、题目、答案位置、评分标准 |
| digest | 镜像的指纹——锁定版本，防止图纸被偷偷换掉 |
| TCR | 腾讯云镜像仓库（图纸仓） |
| COS | 腾讯云对象存储（档案室） |
| PUBLIC / SANDBOX 模式 | 考场能上网 / 考场断网 |
